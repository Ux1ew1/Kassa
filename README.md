# Kassa React

Веб-приложение кассы на React с админ‑панелью и локальным API сервером для хранения меню.

## Возможности

- Просмотр меню и добавление товаров в чек
- Несколько чеков, подсчет суммы и сдачи
- Поиск по меню и фильтрация по категориям
- Админ‑панель для управления рабочими меню и позициями
- Импорт нового меню по фото через Polza AI
- Сохранение чеков в localStorage
- Меню хранятся в `data/menu.json`

## Стек

- React 18
- React Router
- Vite
- Node.js сервер (`server.js`)

## Быстрый старт (разработка)

1. Установите зависимости:
```bash
npm install
```

2. Запустите API сервер:
```bash
npm run server
```

3. Запустите frontend dev‑сервер:
```bash
npm run dev
```

Frontend доступен на `http://localhost:5173`, API — на `http://localhost:3000`.
Vite автоматически проксирует `/api` запросы на backend.

## Продакшен

1. Соберите проект:
```bash
npm run build
```

2. Запустите сервер (он обслуживает и API, и статику):
```bash
npm start
```

Приложение будет доступно по адресу `http://localhost:3000`.

## API

- `GET /api/menu` — получить активное меню
- `PUT /api/menu` — сохранить активное меню
- `GET /api/menus` — получить список меню и активное меню
- `POST /api/menus` — создать новое меню
- `PUT /api/menus/:id` — обновить меню
- `DELETE /api/menus/:id` — удалить меню
- `POST /api/menus/:id/activate` — сделать меню активным
- `POST /api/menus/import-photo` — распознать фото меню или создать меню из предпросмотра

Формат активного меню:
```json
{
  "items": [{"id": 1, "name": "...", "price": 0, "show": true, "category": "напитки"}],
  "activeOrder": [1, 2, 3]
}
```

Для импорта по фото создайте локальный файл `config.local.json` по примеру
`config.example.json`:

```json
{
  "polzaAiApiKey": "ваш_ключ_polza_ai"
}
```

Файл `config.local.json` не коммитится, потому что добавлен в `.gitignore`.

## Переменные окружения сервера

- `HOST` — хост сервера (по умолчанию `0.0.0.0`)
- `PORT` — порт сервера (по умолчанию `3000`)
- `PUBLIC_URL` — внешний URL, который выводится в логах
- `PREFERRED_INTERFACE` — предпочтительный сетевой интерфейс
- `PREFERRED_INTERFACES` — список интерфейсов через запятую

## Учёт товаров и отчёты смен

Управление разделено на три страницы с общей навигацией:
`/admin` — меню и редактирование позиций; `/ai-menu` — распознавание меню по фото;
`/reports` — подготовка товаров, количественный учёт, смены и отчёты.
ИИ-импорт открывается как самостоятельная страница.

На странице отчётов выберите меню для подготовки товаров. Этот выбор не
переключает рабочее меню сотрудников. До первой продажи можно включить учёт,
задать начальные остатки, провести поступления или добавить новый товар
с названием, ценой и количеством. Добавление товара не создаёт продажу или смену.
Если учёт выключен, новые позиции добавляются без количества; включите учёт,
чтобы задать остатки. При добавлении в открытой смене начальное количество
новой позиции записывается как поступление.

Настройка «Состав отчёта» общая для кассы и хранится на сервере. «Все товары из
меню» включает непроданные позиции; «Только проданные товары» оставляет только
товары с продажами и относящиеся к ним изменения количества. Выбор применяется
к текущей таблице, архиву и скачиваемым XLSX/CSV. Полная исходная история
сохраняется, поэтому режим можно менять в любой момент без потери данных.

На странице отчётов выберите меню и откройте «Начальные остатки и настройки учёта». Учёт
включается сразу для всего меню: задайте целое неотрицательное количество
каждой позиции. Выберите автоматический стоп-лист при нуле либо продажу в минус.
Для новых позиций в меню с включённым учётом начальный остаток равен нулю:
задайте его поступлением. Идентификаторы новых товаров не переиспользуются после удаления.

Продажа записывается на сервер при завершении непустого чека. Все сотрудники
должны открывать адрес одного сервера: его телефон или компьютер хранит общие
остатки и смены. Открытые чеки по-прежнему сохраняются в браузере каждого
сотрудника. При нехватке товара чек остаётся открытым, списаний не происходит.
При потере ответа чек защищается от редактирования до повторного завершения:
повтор не создаст вторую продажу, в том числе после перезагрузки страницы.

Раздел «Смены и отчёты» на странице отчётов позволяет закрыть смену, просмотреть текущий
отчёт или архив и скачать XLSX/CSV. Смена общая для всех меню и начинается
с первой продажи; переход через полночь её не закрывает. После закрытия
следующая продажа автоматически создаёт новую смену. Незавершённые чеки
в закрытый отчёт не включаются. Управление доступно через админку без PIN.

Настройки учёта доступны между сменами. В течение смены используйте
«Поступление или корректировка» с обязательной причиной; изменение количества
попадёт в отчёт. Формула: начало + поступления + корректировки − продажи = остаток.
Отчёты включают и продажи без количественного учёта: вместо остатков ставится прочерк.
Продажи по разным ценам показываются отдельными строками; остатки приведены
один раз в итоговой строке товара. Не суммируйте итоговую строку повторно
со строками продаж по ценам; общая выручка вычисляется из самих продаж.

Имя скачиваемого файла содержит дату и время первой продажи смены и её
идентификатор. Даты отображаются в часовом поясе сервера, указанном в отчёте.
XLSX содержит оформленную таблицу и отдельный лист поступлений/корректировок;
CSV — UTF-8 с BOM и разделителем `;`. Скачивание сохраняет снимок отчёта
на устройство, с которого запрошен файл; архив остаётся на сервере.

«Очистить отчёты» требует подтверждения и необратимо удаляет архив и текущую
историю всех сотрудников. Остатки сохраняются. Служебные идентификаторы
обработанных чеков остаются без состава продаж, чтобы повтор старого запроса
не списал товар второй раз. Закрытие смены и очистка — разные действия.

Данные учёта хранятся в `data/accounting.json`, отдельно от `data/menu.json`;
файл исключён из Git. Сохраняйте его при переносе сервера и резервном копировании.
Для отдельного каталога данных можно задать `DATA_DIR`; в нём сервер ожидает
`menu.json` и хранит `accounting.json`. Работать с одним каталогом должен один процесс сервера.
При ошибке чтения учёта сервер блокирует запись вместо сброса остатков.
Для обновления установите зависимости, пересоберите приложение и перезапустите сервер:

```bash
git pull origin Kassa-2
npm install
npm run build
npm start
```

Проверки: `npm test`. Браузерный сценарий дополнительно запускается, если заданы
`KASSA_PUPPETEER` (путь к пакету puppeteer-core) и `KASSA_BROWSER` (Chrome/Edge).
Он использует отдельный временный каталог и изолированные профили, не рабочую кассу.
